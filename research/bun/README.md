# Issue #10: Bun research spike

**Recommendation: drop the production switch for now; keep Node.** Bun runs after
small compatibility changes, but the benefits do not justify supporting another
runtime and deployment path yet. This branch is disposable research, not a
production runtime migration.

## Measurements

Measured 2026-11-16 on an Apple M4, 16 GiB RAM, macOS 26.6.2 arm64, at application
commit `1862f14`. Node v22.22.3 versus Bun 1.4.4. SQLite differs too:
better-sqlite3 uses 3.53.2; Bun uses macOS SQLite 3.51.0. These compare the usable
runtime/driver combinations, not just JavaScript engines.

| Measurement | Node | Bun |
|---|---:|---:|
| Startup to `/ready`, median of 8 fresh runtime directories | 128.6 ms | 104.4 ms |
| Idle RSS one second after readiness, before account setup | 84.9 MiB | 59.8 MiB |
| RSS after 10 minutes of traffic | 100.2 MiB | 80.6 MiB |
| Median sampled RSS during traffic | 100.4 MiB | 80.8 MiB |
| Median routed request latency | 9.07 ms | 7.77 ms |
| Median added latency above the direct mock | 8.90 ms | 7.61 ms |
| Routed request p95 | 12.16 ms | 16.48 ms |
| Successful measured requests / errors | 3,001 / 0 | 3,001 / 0 |
| Privacy filter loaded and one inference, separate process RSS | 1,282.9 MiB | 1,738.0 MiB |

The 600-second workload sends 5 requests/second **per runtime** to a fast local
OpenAI-compatible provider. Both servers run on the same machine simultaneously;
75% of requests use automatic routing and 25% name the model. Each uses its own
fresh database, the existing FULL/WAL durability settings, 50 warmup requests,
and no privacy model. Workers, external metadata refresh and analytics are off.
The mock's median direct HTTP latency was 0.165 ms. This is controlled synthetic
traffic, not live provider traffic. Startup polling has 5 ms resolution.

Other compatibility checks and the weight download ran during portions of the
long run. A separate quiet 30-second confirmation run gave Node/Bun median
latency 10.17/8.75 ms and p95 13.62/20.04 ms, supporting the same conclusion.
RSS fluctuates with collection: sampled ranges were 66.1–118.8 MiB on Node and
67.5–96.3 MiB on Bun. One final RSS sample is not a memory ceiling.

The actual `openai/privacy-filter` q4 model ran on CPU in both runtimes, from the
same local cache. Its weights are 917,120,144 bytes; the revision and raw
measurements are in `model-results.json`. Library-import RSS alone was 85.8 MiB
on Node and 70.6 MiB on Bun. The model dominates; Bun was about 455 MiB larger
after inference in this probe. A single inference is a compatibility check, not
a model-speed benchmark. The existing privacy service already loads lazily and
unloads after idling, so laziness is not a new Bun benefit. Immediate `dispose()`
did not return most RSS to the OS in either probe.

## Compatibility and blockers

- Unmodified `bun server/index.js` exits immediately because `better-sqlite3` is
  unsupported. `sqlite.js` adapts `bun:sqlite` behind `server/db/database.js`:
  `pragma`, connection-open state, and missing-row `get()` semantics. Existing
  migrations, named bindings, transactions and foreign-key error codes work.
- Native bcrypt 6.0.0 works, including verification of hashes generated by Node.
  **Keep it.** `Bun.password.verify` passed short and Unicode fixtures but failed
  an existing bcrypt hash made from a 100-byte password. It is not a safe
  drop-in replacement for all current passwords.
- Transformers 4.3.2 and onnxruntime-node 1.30.0 import, load the real q4 privacy
  model and perform inference under both runtimes. The production model worker's
  fork/advanced-serialization IPC is checked separately by `worker-probe.cjs`.
- Express 4.22.3, ws 8.22.0, compression 1.8.2, zod 3.25.76, otplib 13.5.0 and
  dotenv 16.6.1 load and are exercised by the passing API/unit suite.
- Plain `bun test` is not equivalent to `node --test`: files share module/runtime
  state, and the loopback helper uses Node's private `_listen2`. With the small
  public-listen adjustment and one Bun process per file, **738/738 tests across
  73 files pass**. Node also passes 738/738. No application tests were skipped
  or assertions weakened to get this result.

## Installation/deployment audit

- `install.sh` explicitly checks Node/npm and launches `node`. Supporting Bun
  requires explicit runtime selection and an installer for the chosen binary.
- The manager's dependency check explicitly constructs `better-sqlite3` under
  `process.execPath`; that would fail/rebuild repeatedly on Bun. Driver-aware
  checks are needed. Updates still invoke npm, including global installations;
  using Bun as runtime does not remove npm/Node tooling requirements today.
- systemd, launchd and detached server/update launches already use the absolute
  `process.execPath`. They can select Bun when invoked through Bun, but the
  choice must survive later CLI calls, updates and service regeneration. The
  Node shebang currently selects Node by default.
- Docker builds from Node images, installs/rebuilds native Node dependencies,
  and hardcodes Node in the entrypoint and health check. It needs a separate
  runtime-aware target and verification of ONNX/native binaries on Linux.
  Docker could not be built here because its daemon is unavailable.

Linux, x64, real speech/transcription inference, and an installed systemd/update
cycle remain unverified. Do not extrapolate these Mac measurements to a small
Linux host. Reconsider an opt-in dual-runtime effort only if Linux measurements
show a material memory benefit and someone owns its CI/install/update matrix.

## Reproduction

From the repository root, with dependencies installed:

```sh
npm ci
npm install --prefix /tmp/neorouter-bun-spike bun@1.4.4 --no-audit --no-fund
BUN_BINARY=/tmp/neorouter-bun-spike/node_modules/.bin/bun node research/bun/test-suite.cjs
BUN_BINARY=/tmp/neorouter-bun-spike/node_modules/.bin/bun node research/bun/benchmark.cjs
BUN_BINARY=/tmp/neorouter-bun-spike/node_modules/.bin/bun node research/bun/dependencies.cjs
python3 research/bun/download-model.py --cache /tmp/neorouter-bun-spike/model-cache
MODEL_CACHE=/tmp/neorouter-bun-spike/model-cache node research/bun/model-probe.cjs
MODEL_CACHE=/tmp/neorouter-bun-spike/model-cache /tmp/neorouter-bun-spike/node_modules/.bin/bun research/bun/model-probe.cjs
MODEL_CACHE=/tmp/neorouter-bun-spike/model-cache node research/bun/worker-probe.cjs
MODEL_CACHE=/tmp/neorouter-bun-spike/model-cache /tmp/neorouter-bun-spike/node_modules/.bin/bun research/bun/worker-probe.cjs
```

The download uses about 902 MiB and lives outside the checkout. Benchmarks create
isolated temporary runtime directories and remove them afterward; no existing
user runtime or provider credentials are used. Result artifacts contain counts,
timings and memory only. Background workers are deliberately disabled in the
benchmark; optional production services need their own sustained tests.

References: [Bun SQLite API](https://bun.sh/docs/runtime/sqlite),
[the actual model](https://huggingface.co/openai/privacy-filter), and repository
sources cited above. Raw results and reproducible probes are in this directory.
